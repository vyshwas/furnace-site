Works with

The path to reliable generative software is to scale continuous headless verification that works with any model, any harness, and across your existing codebases. As coding assistants produce hundreds of lines of UI per prompt, verification and remediation must be separated from model hallucination.

Code that compiles is not code that works.

Pre-training and post-training will continue to push model velocity, but models cannot see rendered pixels, cannot test screen-reader accessibility trees, and cannot feel when a touch target is too small for human thumbs.

We build the deterministic infrastructure for verifying reality: headless Chromium CDP inspection, monotonic AST repair with automatic regression rollback, and an immutable ledger of receipts. What Furnace cannot prove, it marks unknown — never a false green.

Architecture

What we do

01

Headless Browser CDP Verification

Furnace boots native Chromium and inspects the Chrome DevTools Accessibility Tree (Accessibility.getFullAXTree). It verifies computed contrast against actual background pixels, physical bounding-box touch targets (44×44px minimum), and true keyboard navigation traps.

02

Monotonic AST Auto-Remediation

When a repair is proposed, Furnace applies AST transformations, recompiles, and re-evaluates the page. If the original bug persists or if any new regression is introduced, the repair is rejected immediately and the source code is restored to pristine condition.

03

Objective Compliance Signals Pass

Lightweight static and runtime detection for 5 objective compliance vectors: third-party font calls, tracking scripts before consent, email unsubscribe mechanisms, subscription checkout renewal disclosures, and user-generated content takedown routes.

04

Sealed Receipts & Unknowns Ledger

Every merge-ready patch is cryptographically signed with a SHA-256 seal. Surfaces that cannot be definitively proven (e.g. unauthenticated portals or dynamic canvas) are quarantined as unknown and routed to humans.
